# commit — コミットスキル

コミットするときは**必ず本スキルに従う**。デフォルトの「default branch なら先にブランチを切る」挙動は、下記の運用モード分岐に従う場合のみ**本PJでは適用しない**。

## 1. 運用モードの判定

`CLAUDE.local.md`（git管理外）の `## 運用モード` にある**「運用」行だけ**で判定する（プラン名 Max/Pro 等は判定に使わない）。「運用」行が `PR運用` なら PR運用、それ以外・記載なしは main 直接運用。

## 2. 運用ルール

- **コミットはユーザーが依頼したときだけ**。push は明示依頼がない限りしない。
- **`work/` はコミット対象外**（gitignore 済み・一時検証/調査用）。`git add .` ではなく**変更ファイルを名指し**でステージする。
- **main 直接運用**（既定。「運用」行が無い／`PR運用` 以外のとき）… ブランチを切らない・PRを作らない。`main` 上で直接コミットする。
- **PR運用**（「運用」行が `PR運用` のとき）… `main` へは直接コミットしない。
  - `git rev-parse --show-toplevel` 等でカレントを確認し、**worktree 上の feature ブランチにいるなら**そのブランチへ通常どおりコミットする（push・PR作成はユーザーの明示依頼があるときだけ行う）。
  - **カレントが `main` の場合**は直接コミットせず、「main へは直接コミットしない」旨をユーザーに伝えたうえで、worktree + feature ブランチを作成してそこへコミットし push → `gh pr create` する経路（work-issue の受け渡しと同じ）を実行するか中止するかを `AskUserQuestion` で確認する。**既定は確認して指示に従う。黙って main へコミットすることは禁止**。

## 3. 手順

0. **まとまった作業（コード・テスト・フック・スキル・ADR の追加や変更）なら、コミットの前に `reviewer` SubAgent（`mode: artifact`）を通す**。Issue を経由しない作業も対象で、その場合は Issue 番号の代わりにユーザーが依頼した範囲（ゴール）を渡す。`Blocker`/`Major` を直して再レビューで合格してからコミットする。`work-issue` で既に合格している差分と、1行で自明な軽微修正（誤字・リンク切れ等）は省いてよい。
1. `git status` / `git diff` で変更を確認し、無関係な変更を巻き込まないか見る。
2. 関係するファイルだけを `git add <path>` でステージ。
3. 1コミット＝1論点。混在していれば分割する。
4. 下記書式でコミットする。
5. コミット前の検査（`.githooks/`）で止まったら、`--no-verify` などで外さず、指摘に従って直す。ファイル名が伏せられている（「N 番目のファイル」）ときは、Claude がそのファイルを探して開かず、本人に確かめてもらう（伏せた語を会話記録に残さないため）。

## 4. メッセージ書式

```
<type>: <要約>

<本文>
```

- `type`: `feat` / `fix` / `refactor` / `test` / `docs` / `chore`
- 要約は日本語・命令形/体言止めで簡潔に。
- **本文は省略しない**（1行で自明な軽微修正を除く）。**git commit がこのPJの作業ログを兼ねる**——別セッションのClaudeが `git log` だけを読んで「何を・なぜ変更したか」を復元できる粒度で書く。含めるもの:
  - **何を**変更したか（差分の要約ではなく、変更の意図・結果を1〜3文で）。
  - **なぜ**その変更が必要だったか（背景・トリガー）。
  - 関連する Issue / ADR があれば番号・パスで名指しする（例: `関連: #12`, `docs/adr/0003-...md`）。
- 末尾に必ず以下のフッタを付ける（モデル名は実際に使用中のものに合わせる）:

```
Co-Authored-By: Claude <実際に使用中のモデル名> <noreply@anthropic.com>
```

> `work-issue` 経由のコミットは本文に `Closes #<N>` を含めるため Issue へのリンクは自動的に満たされるが、Issue自体が読めない状況でも文脈が追えるよう、本文の要約は Issue本文の丸写しに頼らず自己完結させる。
