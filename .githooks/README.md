# .githooks — コミット前の検査

git のフック一式。`git config core.hooksPath .githooks` で有効にする（入れ方はルートの [README.md](../README.md#コミット前の検査)）。理由は [docs/adr/0004](../docs/adr/0004-treat-as-public-from-day-one.md)。

Claude Code のフック（`.claude/hooks/`）とは別物で、Claude を使わずにコミットしても動く。

`commit-msg` は引数のファイルを検査するので、Issue の下書きの検査にも使う（`.claude/skills/create-issue`）。gitleaks の設定（独自ルール）はルートの `.gitleaks.toml` に置く。

## フック

- `pre-commit`: ステージされた内容（`private/` の拒否・禁止語・gitleaks）。`pre-merge-commit` も同じ。
- `commit-msg`: コミットメッセージ（禁止語・gitleaks）。
- `pre-push`: 送るコミットすべて（[ADR 0011](../docs/adr/0011-scan-before-push-and-whole-history.md)）。メッセージ・作者とコミッター・追加されたファイルのパス名と中身・ブランチ名とタグ名を、禁止語リストと gitleaks で検査する。cherry-pick と rebase のコミットは、ここで止まる。ブランチやタグの削除は検査しない。範囲は `<ローカルsha> --not --remotes=<リモート名>`。リモートを URL で指定した push は範囲を絞れず、全履歴を検査する。
- `scan-history`（手で流す）: ブランチ・タグ・リモート追跡ブランチのすべてのコミットを、`pre-push` と同じ基準で再照合する（ref 名を除く。stash は含めない）。禁止語を足した後や、公開する前に流す。違反が無ければ終了コード 0。

作者とコミッターは、メールが `<ユーザー名>@users.noreply.github.com`（先頭に `<数字>+` が付く形も可）で、名前がそのユーザー名と同じ（大文字小文字は区別しない）であること。コミッターだけは、GitHub の Web 画面でマージしたときの組（名前が `GitHub`、メールが `noreply@github.com`）も許す。この欄には禁止語の照合をかけない。名前を本名にした環境で作ったコミットは止まる。

表示では語・名前・メールを出さない。コミットは短縮ハッシュ、ファイルの中身は blob の短縮ハッシュで示す（入れたコミットは `git log --all --find-object=<ハッシュ>` で探す）。

## 防げないもの

- フックを入れていない別のクローンからの push と、GitHub の Web 画面での編集は、サーバー側では止められない。
- 注釈付きタグのメッセージと、タグを付けた人（tagger）の名前とメールは検査しない。
- 手元に古いリモート追跡ブランチが残っていると（リモートで消えたのに `git fetch --prune` していない場合など）、そこにあるコミットは送る範囲から外れて、push では検査されない。`scan-history` は見る。
- `private/` のファイルが入ったコミットの拒否は、`pre-commit` だけ。push では、その中身を禁止語と gitleaks で検査する。
- gitleaks は、マージコミットの差分を最初の親との差で見る。マージ元のコミットの内容も、マージのたびに再び見る。
- 禁止語の照合は、全角・半角、大文字・小文字、ひらがな・カタカナの違いと、空白・記号・ゼロ幅文字・改行による区切りを吸収する。次は拾わない。
  - 漢字とローマ字の読み替え、区切り以外の文字が間に入る書き方（結合用の濁点など）。
  - 短い語の区切りや改行をまたぐ書き方。偶然の一致を減らすため、区切りを取り除く照合は、ASCII だけの語なら 3 文字以上、ASCII 以外を含む語なら 2 文字以上のものに限る（長さと ASCII かどうかは、語から区切りを取り除いた後で見る。ASCII だけの 2 文字以下、ASCII 以外を含む 1 文字、記号だけの語は、そのままの一致だけ）。
  - 画像とフォントの中身の、区切りをまたぐ書き方。ほぼ乱数のバイト列では短い語が偶然一致しすぎるので、そのままの一致だけ見る。
  - ロックファイル（`pnpm-lock.yaml`）の integrity の値の中。ほぼ乱数の base64 で偶然一致が多すぎるので、値を取り除いてから照合する（[ADR 0013](../docs/adr/0013-exclude-lockfile-integrity-from-denylist-scan.md)）。パッケージ名や URL は今までどおり見る。
- 区切りを取り除く照合は、単語をまたいで偶然一致して止まることがある。場所は行番号で出るので、本人が確かめる。
- 画像とフォントは、UTF-8 として読める部分だけを照合する。圧縮・UTF-16 のメタデータは拾わない。それ以外の形式で文字として読めないファイル（PDF・書庫・Office 文書など）は止める。
- 個人情報の形の検出（gitleaks の独自ルール）は代表的な書き方だけ。UNC パスなどは拾わない。
- バケット名の中のアカウントIDは、`-<12桁>-<リージョン>-an` の形だけ拾う。
- `core.hooksPath` は相対パスなので、`.githooks/` が無いブランチや古いコミットでは、フックは何も言わずに動かない。
