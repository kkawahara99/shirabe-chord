# 0011. push の前に送るコミットすべてを検査し、履歴全体も再照合できるようにする

- **Status**: Active
- **Date**: 2026-11-03

## Context

公開される瞬間は push で、main 直接運用では push が最後の関所になる。[ADR 0004](0004-treat-as-public-from-day-one.md) のコミット時の検査には穴が 3 つある。この決定は、0004 の Consequences にある cherry-pick と rebase の項目（git がフックを呼ばないので検査されない）を補う。

- cherry-pick と rebase で作ったコミットは、検査されない。
- 作者とコミッターの名前とメールは、どの検査にもかからない。本名やプライベートなメールが入りうる。
- 禁止語を後から足しても、コミット時の検査は新しい差分しか見ないので、過去の分に効かない。

## Decision

- push の直前（`pre-push`）に、送るコミットすべてを検査し、通らなければ push を止める。送る範囲は `<ローカルsha> --not --remotes=<リモート名>`（リモートを URL で指定した push は範囲を絞れず、全履歴を見る）。ブランチやタグの削除は検査しない。
- 検査は、コミットメッセージ・作者とコミッター・追加されたファイルのパス名と中身・送る ref（ブランチ名とタグ名）。メッセージとファイルは、コミット時と同じ照合（禁止語リストと gitleaks）を使う。
- 作者とコミッターは、メールが `<ユーザー名>@users.noreply.github.com`（先頭の `<数字>+` は可）で、名前がそのユーザー名と同じであることを求める。コミッターだけは、GitHub の Web 画面でマージしたときの組（名前が `GitHub`、メールが `noreply@github.com`）も許す。この欄は公開してよいユーザー名が入るので、禁止語の照合はかけない。名前やメールを本名にした環境で作ったコミットは止まる。
- 履歴全体の再照合として `scan-history` を置く。ブランチ・タグ・リモート追跡ブランチのすべてのコミットに、ref 名を除く同じ検査をかける。stash は公開されないので含めない。マイルストーンの最後の Issue（`work-issue`）で流し、結果を到達ダイジェストに載せる。
- 禁止語リスト・gitleaks・Python が無いときは、検査できないので止める（コミット時の検査と同じ）。

## Consequences

- cherry-pick と rebase のコミット、作者の名前とメールが、push で止まる。後から足した禁止語は、これから送る分には push で効き、送信済みの分には再照合（`scan-history`）で効く。
- push のたびに gitleaks が数回動く（小さな履歴で数秒）。メッセージの gitleaks は、まとめて 1 回流し、指摘が出たときだけコミットごとに流し直す。
- 防げないものが残る。フックを入れていない別のクローンからの push と、GitHub の Web 画面での編集は、サーバー側では止められない。
- 表示は 0004 と同じ規則で、語・名前・メールは出さない。コミットは短縮ハッシュ、ファイルの中身は blob の短縮ハッシュで示す。

## Why not

- **GitHub 側の「メールを公開する push のブロック」設定だけに頼る**: アカウント全体に効き、他のプロジェクトにも影響が及ぶ。このリポジトリだけに効く、フックでの検査で持つ。
- **CI だけで検査する**: [ADR 0004](0004-treat-as-public-from-day-one.md) の Why not を参照。
