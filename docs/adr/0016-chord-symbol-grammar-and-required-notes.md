# 0016. 読めるコード記号の範囲を固定し、構成音を「必須」と「省略できる」に分ける

- **Status**: Active
- **Date**: 2026-11-03

## Context

[0006](0006-product-scope-and-stages.md) は、投稿された押さえ方が「構成音を全部含む」ことを検証するとした。しかし 13th のように、ギターでは全部を押さえられないコードがある。慣習の省略の規則を先に決めないと、押さえ方の候補の生成も検証も作れない。また、入力の記号のゆれ（全角、`maj7` と `M7` など）をどこまで受けるかも決める必要がある。

## Decision

0006 の「構成音を全部含む」を「**必須の音を全部含む**」に絞り込む。省略できる音は、含んでも含まなくてもよい。コード記号の読み取り（`parseChord`）は、次を返す。

- **読める記号**（これ以外は失敗にする。例外は投げない）
  - 読む前に、前後の空白を除き、NFKC（全角を半角にそろえる正規化）をかけ、`♯`・`♭` を `#`・`b` にする。
  - ルートは `A`〜`G` に `#` か `b` を 0〜1 個。音名の綴りは保たず、ピッチクラスだけを返す。
  - 種類: なし・`m`・`7`・`M7`（`maj7`・`△7`）・`m7`・`mM7`・`6`・`m6`・`9`・`M9`・`m9`・`add9`・`13`・`m7-5`（`m7(b5)`・`ø`）・`dim`（`°`）・`dim7`（`°7`）・`aug`（`+`）・`sus4`・`sus2`・`7sus4`。
  - テンションの括弧は、種類が `7`・`m7`・`M7`（別名を含む）のときだけ。`(b9)`・`(9)`・`(#9)`・`(#11)`・`(b13)`・`(13)` をカンマ区切りで複数可。同じ指定の重複と、`9` と `b9`／`#9`、`13` と `b13` の同時指定は失敗。
  - 末尾に `/音名` でオンコード。ベースは構成音でなくてもよい。
- **必須の音**: ルート、3度（sus は 4度か 2度）、7度か 6度（その種類にあれば）、変化した 5度（`m7-5`・`dim`・`dim7`・`aug`）、テンション（`9` 系と `add9` の 9度、`13` の 13度、括弧のすべて）、オンコードのベース。
- **省略できる音**: 完全 5度、`13` の 9度。11度は `13` に含めない（3度とぶつかる）。オンコードのベースが省略できる音と同じなら、必須に寄せる。
- ルートは省略できない。

## Consequences

- 押さえ方の候補は、必須の音を全部含むものに限られる。この規則を変えると、候補と最適化の結果が変わる。
- 一覧にない記号（`11`・`m11`・`7(#5)` など）は読めない。足すときは、この ADR を supersede する。
- 綴りを保たないので、`C#` と `Db` は同じ結果になる。画面で綴りを出し分けたくなったら、別に決める。

## Why not

- **9th・13th でルートも省略できるとする**: ギター担当がルートを省くことはあるが、ベースが鳴らない押さえ方になり、譜面だけで読む人が誤解しやすい。
- **5度を常に必須にする**: 9th・13th では、5度まで含めると指が届かず、候補が減る。5度は和音の性格を決めないので、省ける。
- **変化した 5度も省略できるとする**: `m7-5`・`dim`・`aug` は 5度がコードの性格を決める。省くと別のコードに聞こえる。
- **オンコードのベースを省略できる音にする**: 譜面が示す一番低い音で、省くと記号と鳴る音が食い違う。
- **`Maj7`・`maj9`・`Csus`・`C7(#5)` などを寛容に受ける**: 受ける範囲を広げるほど、意図しない解釈が混ざる。必要が出た記号から、一覧に足す。
