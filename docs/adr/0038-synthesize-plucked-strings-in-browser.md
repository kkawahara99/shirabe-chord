# 0038. 押さえ方の音は、ブラウザの中で弦の音を合成し、波形を先に作って予約して鳴らす

- **Status**: Active
- **Date**: 2026-11-08

## Context

作曲者がギターを弾かなくても、押さえ方を音で確かめられるようにしたい。音の高さは、コアが押さえ方から求めたもの（`soundingNotes`）を使う。一方で「鳴らす」は [ADR 0006](0006-product-scope-and-stages.md) の 3 つのモードのどれにも属さない、新しい機能になる。サーバー・費用・読み込む音源は増やさない。CSP（`default-src 'self'`。`blob:`・`data:` なし）は変えない。進行は最大 64 コードで、ループもある。

## Decision

- 位置づけ: 3 つのモードの外に、モード 1・2 と同じ「ブラウザの中だけで動く」機能として足す。ログインも通信も要らない。
- 合成: メインスレッドで、弦の撥弦音（Karplus-Strong 法。雑音の入った遅延線を平均で減衰させる）を `AudioBuffer` に作り、`AudioBufferSourceNode` を `AudioContext` の時刻で予約して鳴らす（`pluck.ts`）。録音サンプルは使わない。雑音の乱数は差し替えられる。
- 層を分ける: 波形を作る層（`pluck.ts`）と、周波数と開始時刻を受け取って予約する層（`player.ts`）。予約の層は `AudioContext` の最小の型だけに依存し、テストは偽物で、弦の音の高さと順序・取り消しを見る。
- 波形は MIDI ノート番号ごとに長さ 3 秒を 1 回だけ作って使い回す（コードごと・弦ごとには作らない）。
- 予約は先読み。開始時に今のコードと次のコードの分だけ予約し、半小節ごとのタイマーで、2 小節先までの分を足す（切り替えの前に次が予約済みになる。ループは先頭に戻す）。一度に予約するのは高々 3 コード分。止めるのは、再生中に進行・カポ・固定が変わったとき、別の画面へ移ったとき、タブが隠れたとき。止めるときは、タイマーと予約済みの再生ノードの両方を取り消し、鳴っている音は 5ms でフェードして切る。
- 値: ストラムは低い弦から高い弦へ 25ms ずつずらす。マスター音量は 0.3。音の立ち上がりと止めるときのフェードは 5ms。1 コード = 4 拍 = 1 小節で、コードの頭で 1 回ストラムし、音は自然に減衰させる。テンポは 40〜200（既定 90）。
- 音声は利用者の操作（ボタン）のあとに初めて `AudioContext` を作る（自動再生の規制に合わせる）。

## Consequences

- サーバー・費用・配信物が増えない。ビルドも変わらない。コアも変えない。
- 波形の計算（1 音 3 秒）はメインスレッドで走る。1 音は数ミリ秒で、同じ音は使い回すので、初回の数音の分だけ。
- 実際の音色と音高は、テストでは見ない（予約された波形の音高と時刻だけ見る）。音は人の耳で確かめる。
- 撥弦音は簡素で、ギターらしさは限られる。確かめたいのは押さえ方の和音の響きなので、これで足りる。

## Why not

- **`AudioWorklet`**: 別モジュールのビルドが要り、`blob:`・`data:` で読むと CSP で止まる。事前に `AudioBuffer` を作れば足りる。
- **`ScriptProcessorNode`**: 非推奨で、メインスレッドを塞ぐ。
- **録音サンプル**: 読み込む音源とライセンスの扱いが増え、配信物が大きくなる。
- **ノート番号ごとでなく、コードごと・弦ごとに波形を作る**: 64 コードの進行で作る回数と待ちが増える。
- **全コードを最初に予約する**: 停止と編集のたびに多数の再生ノードを取り消す必要があり、テンポの変更にも弱い。
- **拍ごとに鳴らす・メトロノーム・音色の選択**: 目的は押さえ方の確認で、範囲が広がる。
