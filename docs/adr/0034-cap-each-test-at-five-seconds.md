# 0034. 速いテストの 1 件の上限を 5 秒にし、延長や緩和は検査で止める

- **Status**: Active
- **Date**: 2026-11-07

## Context

CI（`test.yml`）は、プルリクエストのたびに core と web のテストをすべて流す。着手前の実測は web が約 80〜100 秒、core が約 16 秒で、遅いのはごく少数のテストだった（性質テスト 1 件が約 46 秒、64 個まで追加するテストが約 9 秒）。残りの約 500 件は一瞬で終わる。遅いテストは、個別の延長（`it` の第 3 引数に 30_000 など）で通されていた。延長が許されると、遅いテストが黙って増え、待ち時間と CI の実行時間が延び続ける。テストの重さの方針は今まで無かった（[ADR 0001](0001-source-of-truth.md) はテストが What の正本と決めるだけ）。

## Decision

- 速いテスト（`pnpm test` が流すもの）は、1 件 5 秒以内に収める。vitest の既定と同じ値を、`apps/web/vite.config.ts` と `packages/core/vitest.config.ts` の `testTimeout`・`hookTimeout` に明示する。
- 手元で 2 秒以内を目安にする。CI のランナーは手元より遅いことがあり、5 秒ぎりぎりのテストは CI で落ちうるため。2 秒を超え 5 秒以内は、理由を残して許す。
- テストごとの延長はしない（第 3 引数・`{ timeout }`・`vi.setConfig`・フックの第 2 引数・コマンドの `--testTimeout` など）。設定ファイルの上限を 5000 より大きくすることも、`--config` で設定ファイルを差し替えることもしない。
- 遅いテストは、確かめる性質を変えずに速くする（繰り返しの回数や入力の大きさを絞る、確かめる対象でない重い部品を `vi.mock` で軽くする）。`vi.mock` はファイル全体に効くので、差し替えるテストは別ファイルに移す。
- 5 秒を超えるテストが本当に要るときは、延ばさず、別の ADR で次のどちらかを決める: 層の分離（`*.slow.test.ts` と CI での流し分け）か、`--changed`。
- 上の決まりは `.github/tests/test_test_limits.py` が検出して失敗にする。ワークフローの安全の条件を守る `test_workflows.py` とは守るものが違うので、別のファイルに置く。

## Consequences

- 遅いテストは書いた人がその場で速くする。待ち時間が延び続けない。
- 乱数で入力を作る性質テストは、繰り返しを絞るぶん、まれな反例を見つける力が落ちる。操作数の多い網羅が必要になったときは、上の層の分離で遅い層に置く。
- 検査はテストのソースを字句で読む。TypeScript の文法をすべて解釈するわけではなく、別名で取り込んだ `it` や、JSX の本文にある `//`（コメントと読み違える）、設定の後ろからの上書き（スプレッド）、`--root` で別の設定を読ませる書き方は見つけられない。見つけられない書き方は、レビューで止める。

## Why not

- **層の分離を今入れる**: 遅いのは少数のテストで、今の規模では分離の効果が小さい。仕組み（ファイルの命名・CI の流し分け）が増える。
- **`--changed`（変えたファイルに関わるテストだけ流す）を今入れる**: 遅い 2 ファイルが、core と App 全体という依存の根元にある。コードを触るプルリクエストではほぼ全部が流れるので、減らせない。
- **延長を許して、上限だけ見る**: 延長が増え続けるのを止められない。
- **検査を `test_workflows.py` に足す**: あのファイルはワークフローの安全の条件に限る。テストの上限は守るものが違い、同居させると読む人が混ざる。
