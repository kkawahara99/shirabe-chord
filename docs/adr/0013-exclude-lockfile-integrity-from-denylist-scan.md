# 0013. ロックファイルの integrity の値を、禁止語の照合から外す

- **Status**: Active
- **Date**: 2026-11-03

## Context

M1 から、pnpm のロックファイル（`pnpm-lock.yaml`）をコミットする。ロックファイルには、integrity の値（`sha512-` などに続く base64）が依存の数だけ並ぶ。base64 はほぼ英数字だけでできているので、短い ASCII の禁止語が、そのままの一致でも偶然一致しやすい。依存 200 件の模擬のロックファイルに、架空の 3 文字の語 300 語を照合すると、そのままの一致だけで 128 語が一致した。このままでは、依存を足すたびにコミットが止まる。

## Decision

`inspect_files` で、ファイル名（パスの最後の部分）が `pnpm-lock.yaml` のファイルは、読んだ後に SRI の値（`sha(1|256|384|512)-[A-Za-z0-9+/]{27,}={0,2}`。前に英数字・`+`・`/`・`-` が続くものは、パッケージ名や URL の途中なので値とみなさない）を空の文字列に置き換えてから、通常どおり（そのままの一致と区切りを取り除く照合の両方を）かける。置き換えは行の中だけで行い、行番号は変わらない。コミット前・push 前・履歴の再照合のすべてが `inspect_files` を通るので、同じ扱いになる。長さの下限 27 字は、SHA-1 の base64（28 字）に合わせた値で、`sha1-` で始まるパッケージ名を消さないため。

## Consequences

- ロックファイルを足しても、integrity の値の偶然の一致では止まらない。
- integrity の値の中にある禁止語は拾えない。値は pnpm が計算するハッシュで、人が書かないので、本物の禁止語が入る経路は考えにくい。
- パッケージ名・URL・版などの、値以外の部分は今までどおり照合する。
- 判定はファイル名の完全一致だけ。`pnpm-lock.yaml` 以外のロックファイル（`package-lock.json` など）は使わないので扱わない。

## Why not

- **ロックファイルを、区切りを取り除く照合からだけ外す（画像と同じ扱い）**: base64 はほぼ英数字なので、区切りがほとんど無く、そのままの一致でも偶然一致がほとんど減らない。
- **ロックファイルを、照合からまるごと外す**: パッケージ名や URL に禁止語が入っても拾えなくなる。
- **ロックファイルをコミットしない**: 依存の版を固定できなくなる（[ADR 0007](0007-typescript-shared-core.md) の Consequences）。
