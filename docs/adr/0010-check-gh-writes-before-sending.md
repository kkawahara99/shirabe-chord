# 0010. gh で文章を公開する操作は、実行する前に検査して止める

- **Status**: Active
- **Date**: 2026-11-03

## Context

Issue・PR・コメント・ラベル・リポジトリの説明は、公開すると全部読める。書き直しても前の版が履歴に残る（[0004](0004-treat-as-public-from-day-one.md)）。コミットには検査（`.githooks/`）があるが、Claude が `gh` で GitHub に書く文章にはなかった。検査は起票の手順書（スキル）を守ることに頼っており、コメント・PR・`gh api` での書き込みには手順自体がない。権限の確認（ask）は本文の中身を見せない（`--body-file` の中身は承認の画面に出ない）。

## Decision

- Claude Code のフック（PreToolUse、Bash と PowerShell）で、`gh` の書き込みを実行する前に検査する（`.claude/hooks/block-unchecked-gh-writes.sh` と `block_unchecked_gh_writes.py`）。権限の確認を置き換えず、重ねる。
- `gh` の操作を 3 つに分ける。読み取りは素通し。Issue・PR・コメント・ラベル・リポジトリの説明への書き込み（`gh issue create|edit|comment|close|reopen`、`gh pr create|edit|comment|review|close|reopen|merge`、`gh label create|edit`、`gh repo edit`）と、GET 以外の `gh api` は検査して通す。それ以外は「検査の対象外」として止め、本人が実行する。
- 検査する文字列は、識別子（`--repo`・エンドポイント・ユーザー名を含みうる URL など）を除くすべての値と、`--body-file`・`--input`・`-F key=@ファイル` が指すファイルの中身。集めて 1 つの一時ファイルにまとめ、`.githooks/commit-msg` を 1 回だけ呼ぶ。検査の別実装は作らない。コミットと同じ基準（禁止語・gitleaks）で止める。
- 実行前に中身を確かめられない形は止める。標準入力、変数・コマンド置換、存在しないファイル、解析できないコマンド、検査する `gh` の前につながった別のコマンド（同じコマンドの中で作るファイルや `cd` で変わる起点は、フックが動く時点では存在しないため）、行の先頭にない `gh`（`xargs`・波括弧・`if` などの中は追えない。読み取りなら通す）。止めるときは「文章を `work/` のファイルに書き、`--body-file` で渡す。コマンドは 1 本ずつ分ける」と案内する。
- 起票と PR の手順書（`create-issue`・`work-issue`）は、この形で書き直す。

## Consequences

- 公開する文章は、禁止語と秘密情報の形を、投稿の前に必ず通る。出力には一致した語を出さない（ルール番号と、`--body-file` の何行目かだけ）。
- 変数・パイプ・標準入力を使う従来の書き方は通らなくなる。手順は「本文をファイルに書く → 1 本のコマンドで渡す」に決まる。
- 1 回の検査は約 3 秒かかる。
- `$` を含む値は、単引用符の中でも止まる。変数を含む GraphQL のクエリを `gh api` で送る操作は、本人が実行する。
- 範囲外: スクリプトファイルの中身、変数で組み立てた `gh` や `python -c` のような別のプログラムを経由した呼び出し、本人のターミナル、`gh` 以外の経路（`curl`・`wget` は deny 済み。`git push` は別の Issue）。

## Why not

- **手順書（スキル）に任せる**: 今の状態。守られなくても気づけず、手順のない書き込み（コメント・PR・`gh api`）は何も検査されない。
- **確認（ask）だけに頼る**: 承認の画面に `--body-file` の中身が出ない。本文を読まずに許可できてしまう。
- **投稿の後で検査する**: 公開した後になる。消しても版が残る。
- **ラッパースクリプト経由だけを許可し、`gh` の直接実行を deny する**: deny は前方一致で抜けやすく、権限設定が複雑になる。
