# 0005. リソース名を「プロジェクト名-環境名-サービス名-用途」にし、S3 はアカウント・リージョン固定の名前空間を使う

- **Status**: Active
- **Date**: 2026-11-03

## Context

AWS のリソースに付ける名前の規則を、最初のリソースを作る前に決める。名前はあとから変えられないもの（S3 のバケット）があるうえ、名前でログの検索や権限の範囲指定をするときに、サービスの種類が分からないと不便になる。

S3 のバケット名は、従来は全世界で共有の名前空間にあり、他人が先に取れる。2026 年 3 月から、名前の末尾にアカウントIDとリージョンを付ける「アカウント・リージョン固定の名前空間」（`<名前>-<アカウントID>-<リージョン>-an`。`an` は account namespace の略）が使え、そのアカウントだけが作れる。

アカウントIDは、コードやドキュメントに直書きしない（[0004](0004-treat-as-public-from-day-one.md)）。名前を組み立てるためのIDは、渡さずにデプロイ先から引く。

## Decision

- 名前の形は `<プロジェクト名>-<環境名>-<サービス名>-<用途>`。プロジェクト名は変数（`project_name`）で、小文字の英数字の 2〜10 文字、既定は `shirabe`。略さない正式名の `shirabe-chord` は、タグ `Project` の値に入れる。サービス名は AWS のサービスの短い呼び名の小文字（`s3`・`lambda`・`dynamodb`・`cloudfront` など）。用途は小文字の英数字とハイフン（`site`・`api`・`state` など）。
- 環境名は変数（`environment`）で `dev`・`stg`・`prd` のどれか、既定は `prd`。
- リージョンは名前に入れない。S3 のバケットは、アカウント・リージョン固定の名前空間（`bucket_namespace = "account-regional"`）で、`<プロジェクト名>-<環境名>-s3-<用途>-<アカウントID>-<リージョン>-an` の形にする。
- アカウントIDとリージョンは、`data "aws_caller_identity"` と `data "aws_region"` で引く。
- AWS が名前の形を決めているもの（Lambda のロググループ `/aws/lambda/<関数名>` など）は AWS の形に従う。
- 名前は、ルートモジュールごとに 1 か所のローカル値（`locals`）で組み立て、Lambda の関数名・IAM ロール名（64 文字）と S3 のバケット名（63 文字）の上限に収まることを `terraform test` で確かめる。
- すべてのリソースに、タグ `Project`（値は `shirabe-chord`）を付ける。
- 状態ファイル用のバケット（`infra/bootstrap/`）も同じ規則で作る。

## Consequences

- バケット名にアカウントIDが入る。GitHub Actions の公開ログに出うるので、アカウントIDの伏せ字の設定を有効にし、plan の出力は PR のコメントやサマリーに載せない。
- バケット名は作ったあとに変えられない。プロジェクト名は最初のデプロイの前に決めてある。
- 中東の 2 つのリージョン（バーレーン・UAE）では、この名前空間が使えない。
- 同じアカウントの別のリージョンに同じ構成を置くと、IAM ロールなどの名前がぶつかる。複数のリージョンに広げるときは、新しい ADR で決め直す。

## Why not

- **プロジェクト名を 2 文字（`sc` など）に略す**: 何のものか分かりにくい。`shirabe`（7 文字）なら名前の長さに収まり、読める。
- **環境名を名前に入れない**: 環境を増やすと全リソースの名前が変わり、S3 は作り直しになる。
- **リージョンの名前や略号を、すべてに入れる**: 1 リージョンでは区別に役立たず、長くなる。
