# 0014. フックの実行テストは、検査まわりに触れたときだけ、コミットの前に 1 回流す

- **Status**: Active
- **Date**: 2026-11-03

## Context

フックを実際に動かすテスト（`.githooks/test_hooks.py`）は、一時リポジトリで違反するコミットや push が止まることを確かめる。公開前の最後の関所（[ADR 0004](0004-treat-as-public-from-day-one.md)・[ADR 0011](0011-scan-before-push-and-whole-history.md)）を守るテストだが、1 件ごとにフックが Python と gitleaks を起動するので、全体で約 5 分かかる。M1 以降は TypeScript の作業が中心になる。検査に触れない変更でも毎回これを流すと、開発の速度が落ちる。遅さを理由に誰も流さなくなれば、検査の壊れに気づけない。速くする方法は別に扱う（#17）。ここでは、速さとは別に「いつ流すか」を決める。

## Decision

- テストを 2 つに分ける。速いテストは `python -m unittest discover -s .githooks -p "test_commit_guard.py"`。全体は `python -m unittest discover -s .githooks`（コマンドは変えない）。
- 全体を流す条件は、変更が `.githooks/test_hooks.py` の `COPIED` に入っているパスに触れたとき、または gitleaks の実行ファイルを入れ替えたとき。補足: 今の `COPIED` は `.githooks/`・`.gitleaks.toml`・`.gitignore`。判定の手順は `work-issue` に置く。
- 流すタイミングは、コミットの前だけ。作業の往復（レビューを含む）では流さない。落ちたら直し、通るまで流し直す。直した変更が `COPIED` のパスに及ぶなら、再レビューする。
- 「テストコマンドがすべて通る」は、`CLAUDE.md` に載っているテストコマンドのうち、フックの実行テスト（`.githooks/test_hooks.py`）だけを条件付きとし、ほかは毎回流して通ることを指す。速いテストのほか、今あるもの・後から足されるものを含む。フックの実行テストは、上の条件に触れたときだけ、コミットの前に 1 回流して通ることを指す。
- 判定の仕組み（スクリプト）は足さない。

## Consequences

- 検査に触れない変更では、約 5 分かかるテストを流さずに済む。
- 検査に触れる変更では、コミット前に必ず 1 回、全体が通ることを確かめる。検査を弱めない。
- 条件に触れたかどうかの判定は、人（Claude）が手順に沿って行う。見落とせば全体が流れないまま入る。仕組みで守らないことを引き受ける。
- 一時リポジトリに写すパスの一覧（`COPIED`）が変わっても、決定の書き方は条件で持つので食い違わない。

## Why not

- **毎回全体を流す**: 検査に触れない変更でも約 5 分かかる。
- **push の直前のフック（`pre-push`）で全体を流す**: push のたびに約 5 分かかる。さらに、テストは `.githooks` ごと一時リポジトリに写してコミットと push をするので、写し先のフックがまたテストを起動し、無限に入れ子になる。
- **コミット前のフック（`pre-commit`）で自動で流す**: 上と同じ入れ子に加え、フックの中は `GIT_INDEX_FILE` などの環境変数が引き継がれ、テストの中の git が意図しないリポジトリに作用するおそれがある。
