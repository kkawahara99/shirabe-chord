# 0009. 全体構成図は、予定のスナップショットとして README にだけ置く

- **Status**: Active
- **Date**: 2026-11-03

## Context

[0001](0001-source-of-truth.md) は、構成図をコミットせず、コードから都度生成するとしている。手書きの図は、コードの変更で自動更新されず腐るためである。

一方で、このリポジトリは公開される。入口の README に全体像の図があると、読む人が理解しやすく、説明もしやすい。いまはアプリのコードがなく、生成元がない。

## Decision

- README の冒頭に、全体構成図を 1 組（ライトとダークの画像）だけ置いてよい。0001 の「構成図をコミットしない」の例外とする。ほかの図は、これまでどおりコミットしない。
- 図の下に、作成した日付と「予定」であることを書く。コードがあるもの（`infra/` など）とないものは、図の中で区別する。
- コードから図を生成できるようになったら、README の図を、生成した図に差し替える。
- 図を作り直すときは、描かれた文字（アカウント ID・名前・ドメインなど）を目で確かめる。コミット前の検査は、画像の中の文字を見ない。

## Consequences

- 実装が進むと図は食い違う。日付を書くので、古さは読む人に分かる。直すのは人。
- 0001 は Active のまま残る。CLAUDE.md と、構成図を扱う 2 つのスキル（`generate-diagram`・`aws-architecture-diagram`）の「コミットしない」には、この例外への一言を足す。

## Why not

- **0001 のまま、図をコミットしない**: 生成元がなく、公開リポジトリの入口で全体像を示せない。
- **Mermaid（テキスト）で書く**: 差分が見え、コミット前の検査も効く。ただ、AWS 公式アイコンと枠の表記で見せたいという目的に合わない。
- **0001 を書き換える・supersede する**: 「コードから生成する」という大原則は変えない。例外は 1 か所だけで足りる。
