# 0022. 譜面を主役にし、編集欄は開閉できる左のパネルにして、項目をタブで分ける

- **Status**: Active
- **Date**: 2026-11-05

## Context

画面は、進行のボタン → 編集の部品 → 最初のコードの押さえ方の候補 → 結果の図の順に縦に並んでいた（[0019](0019-web-screen-with-vite-and-react.md)・[0020](0020-build-progression-by-selection.md)）。編集の部品が画面の大半を占め、押さえ方の図を見るたびに下へスクロールが要る。この作業は、編集と確認のくり返しなので、図と編集欄が同時に見えることが要る。目標は、幅 1280×高さ 800 で 4 コードの図が、スクロールせずに編集欄と同時に見えること。

## Decision

- 画面の高さを使い切り、ヘッダーの下を、編集パネルと譜面に分ける。譜面と編集パネルは、それぞれの中でスクロールする。DOM の順は ヘッダー → 編集パネル → 譜面で幅によらず同じにし、幅 1024px 未満では CSS の `order` で編集パネルを下に出す。
- 幅 1024px 以上では、左に編集パネル（340px）、右に譜面（4 列）を置く。閉じると 44px の帯に「編集を開く」のボタンだけが残り、譜面は 4 列のまま図が大きくなる。幅 1024px 未満では、編集パネルを画面の下に置き（高さは画面の 46% まで）、閉じると消す。
- 譜面は、1 コード 1 枚のカードで並べる。カードのどこを押しても選択でき、記号のボタンの `::after` をカード全体に広げて実現する。ボタン名は記号だけにし、番号と図（`<figure>`）はボタンの外に置く。
- 編集パネルは「コード」（根音・種類）・「テンション・ベース」・「押さえ方」のタブに分ける。「押さえ方」は 1 番目のコードを選んでいて候補があるときだけ出す。タブは `aria-pressed` のボタンにする。
- タブの規則: 選択中のコードが変わると（カードの選択・追加・選択中の削除）「コード」に戻す。編集で記号が変わっても戻さない。手の位置のボタン（ヘッダー）は「押さえ方」にする。開閉ではタブを保つ。「押さえ方」を出せない状態なら、描画のときだけ「コード」として扱う。
- 開閉の規則: 閉じている間は、カードに選択の印を出さず、選択の番号だけ覚える。帯のボタン・カード・「＋ コードを追加」・手の位置のボタンで開く。開いているときに選択中のカードを押しても閉じない（閉じるのは「閉じる」だけ）。閉じている間のコードの削除では開かない。フォーカスは、閉じると選択中のカードへ、帯で開くと「閉じる」へ移し、そのほかの開き方では動かさない。
- 「押さえ方」タブの候補の図は、折り返して並べ、編集パネルの縦スクロールで見る。横スクロールと「←」「→」のボタンは置かない。
- 開閉の状態は保存しない。

## Consequences

- 図を見るためのスクロールが要らなくなる。M3 の候補の選び直しは、「押さえ方」タブを広げる形で足せる。
- 開閉・タブ・選択の組み合わせが増えるので、不変条件（選択の番号は範囲内、出ているタブは出せるタブ、など）を、乱数で操作を重ねるテストで守る。
- 配置・幅・当たり判定の見た目は jsdom で測れないので、人が確かめる（[0019](0019-web-screen-with-vite-and-react.md) と同じ）。
- [0020](0020-build-progression-by-selection.md) の「ボタンの一覧と、選んだ 1 つを編集する部品」は、ボタンをカードに置くだけなので有効のまま。

## Why not

- **編集欄を下に固定する案**（幅 1024px 以上では採らない）: 縦が短い画面で、譜面の高さが足りない。幅 1024px 未満では、横幅が足りず左のパネルが置けないので、この形を使う。
- **カードの横に小窓で編集する案**: 隣のカードを隠す。
- **開閉の状態の保存**: 進行を保存していないので、開閉だけ覚えても意味がない。
- **候補の図を横スクロールで並べる**: 編集パネルが縦にスクロールするので、横にもスクロールが要ると操作が二重になる。「←」「→」のボタンも要らなくなる。
- **`role="tab"`（矢印キーでタブを移る操作）**: 矢印キーの操作まで作る手間に対し、今の `aria-pressed` のボタンの形で足りる。
