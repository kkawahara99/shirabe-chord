# 0019. 画面は Vite ＋ React で作り、押さえ方の図は自前の SVG で描く

- **Status**: Active
- **Date**: 2026-11-04

## Context

モード 1・2 はサーバーを持たない静的サイト、モード 3 も画面はブラウザで動く（[0006](0006-product-scope-and-stages.md)）。コアはブラウザとサーバーで共有する TypeScript で、ビルドせずに画面が取り込む（[0007](0007-typescript-shared-core.md)・[0015](0015-pnpm-workspace-and-dependency-guards.md)）。モード 2・3 では、候補の選び直しや掲載・コメントなど、画面の状態が増える。

## Decision

- 画面（`apps/web`）は Vite でビルドし、React で書く。出力は静的ファイルだけにする。
- 押さえ方の図は、React のコンポーネントが SVG を直接描く。図のライブラリは入れない。
- 入力の文字は React の通常の描画（テキストとして出す）だけで表示し、`dangerouslySetInnerHTML` は使わない（テストで確かめる）。
- 画面のテストは vitest ＋ Testing Library（jsdom）で書く。

## Consequences

- モード 2・3 の画面は、同じコンポーネントを土台にできる。React は例と周辺のライブラリが多く、状態の管理も React の標準の機能（hooks）で足りる。
- 依存は増える（react・react-dom・vite など）。公開から 7 日待つ決まり（0015）に従う。
- jsdom は配置を計算しないので、幅 360px での折り返しなど見た目はテストで確かめられない。人が確かめる。

## Why not

- **素の TypeScript**: 依存は最も少ないが、モード 2・3 で増える画面の状態（選び直し・ログイン・コメント）を自前で管理することになる。
- **Svelte**: React に比べ、例と周辺のライブラリが少ない。
- **Next.js などのサーバーで描くフレームワーク**: モード 1・2 は静的サイトで足りる（0006）。サーバーの実行環境を持つと、運用と費用が増える。
- **図のライブラリ**: 描くのは 6 本の弦と数個の印だけで、ライブラリの依存を増やす理由が無い。
