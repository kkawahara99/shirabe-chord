# 0004. 最初から公開リポとして扱い、本人や環境を特定する情報を守る

- **Status**: Active
- **Date**: 2026-11-03

## Context

このリポジトリはポートフォリオとして公開する。非公開の期間に書いたコミット・コミットメッセージ・Issue・PR・コメント・GitHub Actions のログも、公開すれば全部読める。Issue や PR は本文を直しても前の版が履歴に残り、タイトルの変更もタイムラインに残る。公開してから消しても、遅い。

守る対象は、作者本人を特定する情報（氏名・顔写真・連絡先・住所・所属先・顧客）と、環境を特定する情報（AWS のアカウントID・ARN・メールアドレス・ローカルの絶対パス・秘密の値）の2つ。名前を伏せても、業界・時期・規模などの組み合わせで特定されうる。

## Decision

- 最初のコミットから、公開済みのリポジトリと同じ基準で扱う。
- 次をコミット・コミットメッセージ・Issue・PR・コメントのどこにも書かない。
  - 本人を特定する情報、私生活、所属先や顧客を特定できる情報。
  - AWS のアカウントID・ARN・メールアドレス・ローカルの絶対パス。手元では変数（`*.tfvars`、gitignore 対象）、GitHub Actions では Secrets で渡す（Variables はログで伏せ字にならない）。
- コミットのたびに、git のフック（`.githooks/`）で検査する。禁止語リスト（`private/denylist.txt`、gitignore 対象。作者が本人を特定する語を書く）との照合、`private/` のステージ拒否、gitleaks（既定のルールと、個人情報・識別子の独自ルール）。AI は禁止語リストを読まない（照合はスクリプトで行う）。
- Issue は、起票する前にローカルの下書きでレビューと検査を済ませる（検査フックは Issue にかからないため）。
- 検査を外す操作（`--no-verify`、`core.hooksPath` の変更など）は、Claude Code のフックで止める。
- 公開する前に、履歴全体を検査する。

## Consequences

- 公開の直前に慌てて履歴を洗う必要がなくなる。
- 検査は代表的な書き方だけを拾う。氏名や住所は形で拾えないので、禁止語の照合と、レビュー（`reviewer`）の点検に任せる。
- cherry-pick と rebase で作られるコミットは、git がフックを呼ばないので検査されない。

## Why not

- **非公開で作り、公開するときに履歴を1つにまとめる**: Issue・PR・Actions のログまでは消せず、まとめた履歴に頼ると途中の漏れに気づきにくい。
- **検査を CI だけに置く**: CI に載る前（ローカルのコミットとコミットメッセージ）で止めたい。CI は後から足してもよい。
