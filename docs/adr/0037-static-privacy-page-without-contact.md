# 0037. プライバシーポリシーを静的なページとして置き、問い合わせ先は書かない

- **Status**: Active
- **Date**: 2026-11-08

## Context

Google の同意画面を「本番」にするには、ホームページとプライバシーポリシーの URL が要る（[0035](0035-share-by-unguessable-url-with-google-login.md) の共有のログインに使う）。「テスト中」のままだと、テストユーザーに足した人しか共有できない。サイトにはまだそのページが無い。

## Decision

- ポリシーは `apps/web/public/privacy.html` に置く。画面（React）の一部にしない。CloudFront の振り分けは変えずに `/privacy.html` で配られる。
- 見た目は `apps/web/public/privacy.css` に分ける。CSP（[0023](0023-static-site-delivery-with-cloudfront-and-s3.md)）が `default-src 'self'` でインラインのスタイルとスクリプトを止めるため、ページに `<style>`・`style=""`・`<script>` は書かない。`public/` のファイルは Vite を通らず `style.css` は読めないので、色の変数を写し、値の一致をテストで守る。
- `<meta charset="UTF-8">` を入れる（`aws s3 sync` は charset を付けないため）。
- 中身の正本は ADR 0035 とコード（`infra/app`・`apps/api`・`apps/web`）。食い違ったらコードに合わせる。
- 問い合わせ先は書かない。ログインの記録が残ること、消す手段が無いことは書く。
- 画面の下端に「プライバシーポリシー」のリンクを置く。共有が設定されているとき（ログインのボタンを出す条件と同じ）だけ出し、印刷では隠す。

## Consequences

- 画面の配信と同じ経路で更新できる。文面を変えるにはサイトを再デプロイする。
- 文面とコードの食い違い（Google から受け取る範囲、ログの保持日数）は、テストが見つける。それ以外の事実は、コードを変えた人が文面も直す。
- 問い合わせの窓口が無いので、利用者は削除や問い合わせを頼めない。個人情報は持たない（0035）ことと、共有は本人が画面から削除できることで足りるとみる。Cognito のユーザーの記録だけは、共有を消しても残る。
- ロゴを登録しないので、Google の審査は要らない見込み。ただし Google がドメインの所有確認を求めたら、独自ドメインが要るかもしれない。

## Why not

- **画面（React）の一部としてポリシーを作る**: 配信の振り分けと CSP の確認が増え、Google に渡す URL が画面の状態に左右される。静的ページなら読み込むものが無く、壊れにくい。
- **`<style>` をページに書く（CSS を分けない）**: CSP が止める。CSP を緩めるのは、ポリシーのページ 1 枚のために守りを下げることになる。
- **`style.css` を共有する（Vite を通す）**: ポリシーが画面のビルドと同じ入口になり、静的ページでなくなる。写す色は数個で、テストが一致を守る。
- **問い合わせ先（メールアドレスなど）を書く**: 公開するリポジトリに、本人や所属につながる連絡先が残る（[0004](0004-treat-as-public-from-day-one.md)）。専用のアドレスを作る手間と受け付ける運用に見合う利用者がまだいない。
