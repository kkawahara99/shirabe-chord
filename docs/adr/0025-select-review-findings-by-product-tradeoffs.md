# 0025. 音楽面のレビューの指摘のうち、5件だけを課題にし、残りは見送る

- **Status**: Active
- **Date**: 2026-11-06

## Context

ギターのプロの目線で画面とコアの出力をレビューし、多くの改善案が出た。全部を足すと、選択肢と注意書きが増えて画面が散らかり、作ったばかりの決定（#31 の図の向き、[0020](0020-build-progression-by-selection.md)）をやり直すものも混じる。そこで、画面設計・企画の目線でトレードオフを切り分け、効果が大きく、費用と画面の増加が小さいものだけを課題にした。見送った案は、同じ議論の蒸し返しを防ぐために、理由と見直す条件を残す。

## Decision

次の 5 件だけを課題にし、ほかは見送る（見送る案の理由と見直す条件は Why not）。

- #47 コアのコスト: 窮屈な形（開放弦をはさんで同じフレットを別々の指で押さえる）と、鳴る弦が少ない薄い形を選びにくくする。
- #48 画面: 図でルート音の弦を見分けられるようにする。
- #49 画面: 記号を ♯♭ の譜面の表記にし、「第Nポジション」と呼ぶ。標準チューニング・右利き前提を画面に書く。
- #50 画面: 印刷と、押さえ方のテキストコピー。
- #51 カポ: 選べるようにする（扱い方は #51 の ADR で決める）。

## Consequences

- 見送った案は、見直す条件に当たるまで課題にしない。拾うときは、その案を外す新しい ADR を起こす（語彙の拡張なら、種類の一覧を決めた [0016](0016-chord-symbol-grammar-and-required-notes.md) も supersede する）。
- 見直す条件の「声」は、公開後に GitHub の Issue で受け取る前提。

## Why not

見送った案と、見直す条件。

- **オンコードのベース音が構成音でないときの警告**: `C/D` のような正当な使い方まで警告が出て騒がしい。意図しない選択は、図を見れば分かる。見直す条件: 誤って選んだという声が複数出たとき。
- **指番号の表示**: 運指を推定して出すと、誤った番号を渡す。番号が無い図より悪い。小さなカードでは視覚のノイズにもなる。見直す条件: 運指を決定的に決める規則（ADR にできるもの）ができたとき。
- **図を縦向き（コードブックの形）にする**: 横向きは、高いフレットを読み取りにくいという目視確認の結果を受けて #31 で決めたばかりで、やり直しになる。見直す条件: 縦に慣れた利用者から読みにくいという声が複数出たとき。切り替えにする案もあるが、設定が増える。
- **貼り付けでの進行の入力**: 0020 が「必要になったら足す」とした範囲。足すには、自由入力で避けた書き方のばらつきと読めない記号の扱いを、決め直す必要がある。見直す条件: 入力に時間がかかるという声が複数出たとき。
- **小節・拍の構造**: 譜面エディタ化になり、[0006](0006-product-scope-and-stages.md) のスコープを超える。見直す条件は置かない（見直さない）。
- **和音の語彙の拡張（m7(11)・m11・7(♭5)・7(♯5)・6/9・madd9・9sus4・M13）**: 選択肢が増えて編集欄が散らかる。要望のデータもまだ無い。見直す条件: 公開後に、無い種類を求める声が出たとき。足すときは、使用頻度の高い順に 1 つずつ。
- **M7 の別名（`maj7`・`△7`）を選べるようにする**: 表記は 1 つに固定する（0020）。種類の選択肢も増える。見直す条件は置かない。
- **用途別（初心者・バンドなど）のコストのモード切り替え**: 設定が増え、どれが良いか決める材料が無い。重みは、ギター担当の修正結果で調整する前提（0006）。見直す条件: 修正の傾向が、用途ごとに分かれると分かったとき。
- **PDF・画像を自前で作る出力**: ブラウザの印刷から PDF にできるので、自前の生成は要らない（#50）。見直す条件は置かない。
- **おすすめのカポの自動提案**: 先に、カポを選べる形（#51）だけを作る。提案は、カポごとに進行全体の最適化を繰り返すため、ブラウザでの計算量の確認が要る。見直す条件: #51 のあとに、どのカポが良いか分からないという声が出たとき。
- **変則チューニング・左利き**: 条件が増えて決めきれない（[0017](0017-voicing-validity-conditions.md)）。見直す条件は 0017 のとおり。
